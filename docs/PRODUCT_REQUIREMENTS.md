# 知迭 v0.1 产品需求

状态：v0.1

## 1. 产品定位

知迭是面向学习者的掌握学习 Agent。它不以“生成一段答案”为终点，而是持续维护学习状态，通过诊断、渐进引导、独立尝试和迁移验证形成可追溯的掌握证据，再决定下一步学习动作。

v0.1 使用 Python `range()` 验证完整闭环。这是首条纵向切片，不是产品能力边界。

## 2. 目标用户与问题

### 目标用户

正在学习 Python 基础、能够阅读简单代码，但容易混淆参数含义和边界规则的学习者。

### 核心问题

- 普通练习系统只能判断对错，不能区分错因。
- 直接给答案会掩盖学习者是否真正理解。
- 提示后答对常被错误地视为已经掌握。
- 学习状态缺少证据来源，下一步学习建议无法解释。

## 3. v0.1 用户闭环

1. 学习者从首页开始或恢复 `range()` 学习会话。
2. 系统要求学习者独立回答诊断题 `list(range(2, 10, 3))`。
3. Agent 解析答案并识别错因；不同答案必须产生不同诊断。
4. Agent 根据作答历史选择最多三级渐进提示，提示不得直接给出答案。
5. 学习者在提示后答对时，仅记录为“辅助完成”，不能直接判为掌握。
6. 系统要求学习者构造能够生成 `[1, 4, 7, 10]` 的 `range()` 参数。
7. 系统根据实际序列验证等价答案；只有未使用提示且迁移成功，才形成“迁移已验证”证据。
8. Agent 根据证据决定更新或不更新正式掌握状态，并解释下一步动作。
9. 学习者可以查看证据来源和经过隐私处理的工具调用记录。

## 4. 核心领域状态

### 会话阶段 `session_phase`

```text
diagnostic
guided_practice
transfer_check
completed
```

### 掌握状态 `mastery_state`

```text
unassessed
learning
pending_verification
mastered
```

### 证据等级 `evidence_level`

```text
none
assisted
independent
transfer_verified
```

三组状态必须分开保存和展示。例如，会话可以已经完成，但掌握状态仍为 `pending_verification`。

## 5. 关键业务规则

- 系统先规范化学习者输入，再执行确定性错因映射。
- 提示分为三级，并记录实际使用的最高提示级别。
- 提示后答对只生成 `assisted` 证据。
- 迁移题按照执行结果判断，不要求唯一的文本答案。
- 只有无提示迁移成功可以生成 `transfer_verified` 证据并进入 `mastered`。
- 证据不足时必须保留原正式状态，并明确下一步需要什么证据。
- 正式状态只能由后端领域规则更新；可选模型无权直接修改状态。
- Agent Trace 展示动作、输入摘要、输出摘要、结果和错误，不展示模型思维链。

## 6. 功能范围

### v0.1 能力

- 学习首页、学习工作台、掌握证据与记录页面；
- 真实前后端交互；
- 不同答案对应不同错因；
- 三级渐进提示；
- 独立迁移验证；
- 会话、作答、证据和 Agent Trace 持久化；
- 正常闭环以及至少一个证据不足或异常分支；
- 后端规则测试和一次完整流程测试；
- 离线默认可运行，不要求 API Key；
- 清晰的本地启动说明。

### v0.1 非目标

- 登录和多租户用户系统；
- 教师端；
- 文件上传、RAG 和知识库管理；
- 多课程编辑器；
- 不受控的真实代码沙箱；
- 复杂多 Agent 编排；
- 支付、移动客户端和运营后台。

## 7. 产品与合规边界

- v0.1 使用本地体验身份和模拟学习数据，不包含账户认证能力。
- 知迭提供学习辅助和掌握证据，不替代教师的专业判断。
- 不提交或上传真实用户数据、密钥和非公开材料。
- 用户可见文案只描述已经实现并经过验证的模型、工具和效果。

## 8. v0.1 验收场景

### 场景 A：独立掌握

学习者完成诊断与练习，在未请求提示的情况下独立完成迁移题。系统保存迁移证据，更新为 `mastered`，并说明更新依据。

### 场景 B：提示后答对

学习者使用提示后完成当前题。系统记录 `assisted`，但正式状态不进入 `mastered`，下一步要求独立迁移验证。

### 场景 C：证据不足

学习者只有一次正确作答或迁移时使用了提示。系统明确说明证据不足，不更新正式状态。

### 场景 D：异常输入

学习者输入无法解析的文本。系统保留原阶段和证据，给出可操作的格式说明，并记录失败的工具调用。

## 9. 成功标准

- 新用户无需解释即可找到开始入口并完成一条流程。
- 页面清楚区分“当前答对”“辅助完成”和“已掌握”。
- 每次正式状态变化都能追溯到具体证据。
- 不同作答能够真实触发不同路径，不依赖特殊开关。
- 从干净环境可以按文档启动、构建和运行测试。
