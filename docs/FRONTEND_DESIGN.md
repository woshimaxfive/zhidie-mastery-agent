# 知迭前端设计

状态：v0.1

## 1. 设计结论

知迭采用“任务型学习工作台 + 掌握证据视图”，不采用数据驾驶舱，也不采用纯聊天界面。

学习者的主要任务是完成下一次正确尝试并理解为什么；Agent 的决策依据、工具调用和证据通过渐进展开呈现，不与学习任务争夺注意力。

## 2. 信息架构

```text
/                         学习首页
/learn/:sessionId         引导学习工作台
/evidence/:knowledgeId    掌握证据与学习记录
```

信息架构可以扩展课程、教师和设置模块；v0.1 仅展示已有功能的导航入口。

## 3. 学习首页

### 页面目标

回答“接下来学什么，为什么”，并让用户一步进入或恢复学习。

### 内容优先级

1. 当前建议动作和唯一主按钮；
2. 推荐原因；
3. 当前知识点的掌握状态与证据摘要；
4. 最近一次会话的恢复信息；
5. 查看完整证据的次级入口。

### 低保真结构

```text
┌──────────────────────────────────────────────┐
│ 知迭                                  学习记录 │
├──────────────────────────────────────────────┤
│                                              │
│  下一步：确认 range() 的停止值规则            │
│  原因：最近一次作答包含了停止值 10             │
│                                              │
│  [继续学习]                                  │
│                                              │
│  当前状态：学习中     证据：辅助完成            │
│  最近证据：使用一级提示后完成当前题             │
│  [查看掌握证据]                               │
└──────────────────────────────────────────────┘
```

首页不能变成指标卡片集合。v0.1 只有一个知识点时，也不虚构课程进度和排行榜。

## 4. 引导学习工作台

### 页面目标

让学习者完成当前任务，并在不泄露答案的前提下获得适当引导。

### 桌面布局

```text
┌────────────────────────────────────────────────────┐
│ 知迭  Python · range()     诊断 → 引导 → 迁移 → 结论 │
├──────────────────────────────────┬─────────────────┤
│                                  │ Agent 当前决定   │
│ 当前任务                          │                 │
│ list(range(2, 10, 3))            │ 先澄清停止值规则 │
│                                  │                 │
│ range 执行轨迹                    │ 判断依据         │
│ 2 ── 5 ── 8 ── ×10               │ · 当前答案模式   │
│                                  │ · 提示依赖       │
│ 诊断反馈或当前提示                 │                 │
│                                  │ 正式状态         │
│ [填写答案________________] [提交] │ 暂不更新         │
│                                  │ [查看依据与记录] │
└──────────────────────────────────┴─────────────────┘
```

- 主任务区域约占 70%，决策栏约占 30%。
- 每个阶段只有一个主操作。
- 完整 Agent Trace 放在抽屉中，不常驻页面。
- 移动端使用单列布局，决策栏变成底部抽屉。

### 标志性交互：range 执行轨迹

执行轨迹用于呈现参数与序列之间的关系，并贯穿诊断、提示、迁移和证据回顾。

- 初始状态不能直接显示完整答案。
- 提交答案后，仅展示诊断所需的信息。
- 不同提示等级逐步增加边界、步长或执行位置说明。
- 迁移任务改为由目标序列反推参数。
- 轨迹变化必须支持减少动态效果设置。

未来扩展其他编程知识点时，应复用“可解释执行表示”这一原则，而不是强行复用 `range()` 数轴本身。

## 5. 掌握证据与学习记录

### 页面目标

解释当前状态为什么成立，以及还缺少什么证据。

### 页面内容

- 当前掌握状态与最后更新时间；
- 状态更新或未更新的原因；
- 按时间排列的证据账本；
- 每条证据的任务、是否使用提示、结果和证据等级；
- 对应会话和 Agent Trace 的查看入口；
- 下一步需要获得的证据。

“答对”不能直接使用绿色掌握标识。只有 `transfer_verified` 可以使用正式的验证绿色。

## 6. 关键页面状态

每个核心页面必须设计以下状态：

- 初次进入；
- 加载中；
- 正常交互；
- 输入格式错误；
- 证据不足；
- 保存失败但本次输入仍保留；
- 会话版本冲突，需要刷新；
- 完成且掌握；
- 完成但仍待验证；
- 无历史记录。

错误提示必须说明发生了什么、哪些内容已保存以及用户下一步可以做什么。

## 7. Agent 可见性

学生默认只看见：

- Agent 当前决定；
- 简短判断依据；
- 对正式掌握状态的影响；
- 下一步动作。

展开 Trace 后可以看见：

- 工具名称；
- 调用时间；
- 输入摘要；
- 输出摘要；
- 成功、失败或跳过；
- 失败后的处理方式。

不展示模型思维链、系统提示词、密钥、内部异常堆栈或学习者隐私数据。

## 8. 视觉语言

整体气质为“学习笔记 + 程序执行轨迹”，避免装饰性过强的科技展示风格。

### 建议色彩

```text
Ink Navy       #10213F  主要文字
Cobalt         #2F66E8  主操作与焦点
Cyan           #23AFC0  执行轨迹辅助信息
Paper Blue     #F6F9FE  页面背景
Evidence Amber #D99120  证据不足与提示依赖
Verified Green #16866B  迁移已验证
Danger Red     #C63D4F  真实错误
```

### 字体与形态

- 中文界面使用 Noto Sans SC 或等价的开源中文无衬线字体。
- 代码和参数使用 JetBrains Mono 或等价开源等宽字体。
- 使用平面层级、细分隔线和适度圆角。
- 不使用玻璃拟态、大面积渐变、发光描边或满屏卡片网格。
- 焦点、错误和状态不能只依赖颜色表达。

正式引入字体前必须核对许可证和部署体积；未引入时使用系统字体降级栈。

## 9. 响应式与可访问性

- 桌面端主任务和决策栏并排；窄屏下改为单列。
- 关键触控目标不小于 44 × 44 CSS 像素。
- 支持键盘完成作答、请求提示和打开证据。
- 动效遵守 `prefers-reduced-motion`。
- 输入错误关联到具体字段，并由辅助技术读出。
- 代码、轨迹和状态文本满足可读对比度要求。

## 10. v0.1 前端验收

- 三个页面形成连续、可返回和可恢复的真实流程。
- 不同答案在页面上产生不同诊断和下一步动作。
- 提示等级、提示依赖和证据影响清楚可见。
- 学生可以区分当前答对、辅助完成和正式掌握。
- Agent Trace 来自后端真实响应，不是前端写死的静态文本。
- 保存失败、证据不足和会话冲突至少各有明确的界面处理设计。
